# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Contractor performance dashboard for LP First Capital. Scrapes stats from three portals (ContractorConnection, Sedgwick, Alacrity) using Playwright, stores data in an encrypted JSON file, and serves a password-protected static dashboard on GitHub Pages.

## Key Commands

```bash
# Daily update pipeline (decrypt → scrape all sources → re-encrypt data)
npm run update

# Update individual sources
npm run update:cc
npm run update:sedgwick
npm run update:alacrity

# Initial full scrape (all years 2020-2025, then encrypt everything including HTML)
npm run update:initial

# Encrypt/decrypt data manually
npm run decrypt          # stats.json.enc → stats.json
npm run encrypt:data     # stats.json → stats.json.enc (data only)
npm run encrypt          # Full encryption: data + StatiCrypt HTML wrapper

# Local dev server
npm run serve

# Cloudflare D1 metrics mirror (needs data/stats.json, i.e. run decrypt first)
npm run push:d1          # latest snapshot per stream (what CI runs daily)
npm run push:d1:all      # every snapshot + past-year CC totals (backfill / re-sync, idempotent)
npm run push:d1:dry      # no HTTP; print per-stream counts and a sample statement
npm run d1:migrate       # wrangler d1 migrations apply --remote (one-time / on schema change)

# Unit tests (node:test, no framework)
npm test
```

All commands require `STATICRYPT_PASSWORD` in `.env`. Scraper commands also need portal credentials, prefixed per company: `AACTION_CC_*` (username, password, 2FA secret), `AACTION_SEDGWICK_*`, `AACTION_ALACRITY_*`, `ICON_SEDGWICK_*`, `MOYERS_SEDGWICK_*`, `MOYERS_ALACRITY_*`. The D1 commands need `CLOUDFLARE_API_TOKEN` (custom token: D1 Edit, Account Settings Read, User Details Read), `CLOUDFLARE_ACCOUNT_ID`, and `CLOUDFLARE_D1_DATABASE_ID`.

## Architecture

### Data Flow
1. **Scrapers** (`scraper/`) use Playwright to log into contractor portals and extract metrics
2. Data is saved to `data/stats.json` (plaintext, temporary)
3. **D1 mirror** (`scripts/push-to-d1.js`) flattens the snapshots via `scraper/flatten.js` and upserts them into the Cloudflare D1 `metrics` table through the D1 REST API. Runs in CI between scrape and re-encrypt (it needs the plaintext file), with `continue-on-error` and a gate step at the end so a failure still turns the run red without blocking the commit.
4. **Encryption** (`scripts/encrypt-data.js`) encrypts to `data/stats.json.enc` using AES-CBC with PBKDF2 (600k iterations), then deletes plaintext
5. **Dashboard** (`index.html.bak`) decrypts data client-side using the password hash stored by StatiCrypt
6. GitHub Actions (`update-data.yml`) runs the pipeline daily at 6 AM UTC and commits `stats.json.enc`

### File Roles
- `index.html` - Encrypted (StatiCrypt-wrapped) dashboard, generated by `scripts/encrypt.js`. **Do not edit directly.**
- `index.html.bak` - The actual dashboard source code (HTML + inline JS). **Edit this file** for any dashboard/UI changes.
- `data/stats.json.enc` - Encrypted data file, the committed source of truth
- `data/stats.json` - Decrypted data, exists only temporarily during scrape runs
- `.staticrypt.json` - Salt used for encryption/decryption (must not change after initial setup)
- `scraper/flatten.js` - Pure flatteners: `listStreams(stats)` is the one place that knows the stats.json layout; `flattenStats()` turns snapshots into `{company, source, entity, date, metric_key, value, year}` rows
- `scripts/push-to-d1.js` - Pushes those rows to D1 (14-row upserts, 50 statements per request, retry on 429/5xx)
- `migrations/*.sql`, `wrangler.jsonc` - D1 schema, applied with `npm run d1:migrate`. No Worker is deployed.
- `test/*.test.js` - node:test unit tests for the flattener and push script

### Scraper Structure
- `scraper/index.js` - Main orchestrator; runs all company scrapers
- `scraper/contractor-connection.js` - Parameterized CC scraper (creds + target container), used for both A-Action (stats root) and Moyer's (`stats.moyers`)
- `scraper/auth.js` - Auth0 login with TOTP 2FA for ContractorConnection
- `scraper/utils.js` - Shared utilities (data load/save, date formatting, diff calculation, `runStandalone()` helper)
- `scraper/cc.js`, `sedgwick.js`, `alacrity.js` - Standalone entry points for individual scrapers
- `scraper/tabs/` - CC tab-specific extraction logic (assignments, avgTip, poms, reinspections, surveys, qaFeedback)

### Dashboard (index.html.bak)
- Single-page app with all JS inline, uses Chart.js 4.4.1 and Tailwind CSS (CDN)
- Three data source views: ContractorConnection (default), Sedgwick, Alacrity
- CC view has time-period tabs (Daily/Weekly/Monthly/Yearly) with charts and tables
- `getSnapshotsByPeriod()` groups `dailySnapshots` into weekly/monthly aggregations
- `calculateSummary()` aggregates `byType` data into totals for charts

### Data Schema
```
statsData = {
  lastUpdated: ISO string,
  years: { "2026": { assignments: {byType: {...}}, poms: {byType: {...}}, ... } },
  dailySnapshots: [{ date: "YYYY-MM-DD", year, data, summary, diff, previousDate }],
  sedgwick: { dailySnapshots: [...] },
  alacrity: { dailySnapshots: [...] }
}
```

CC data is organized by **tab** (assignments, avgtip, poms, reinspections, surveys, qafeedback) and within each tab by **assignment type** (7 POM types like "Residential POMS", "Commercial POMS", etc.).

### D1 `metrics` table

Primary key `(company, source, entity, date, metric_key)`. `company` ∈ aaction/icon/moyers, `source` ∈ cc/sedgwick/alacrity, `entity` is the Icon location key, the Alacrity contractor label, or `''`. `year` is set for CC rows only (CC data is year-to-date). Past CC years (2020-2025 from `stats.years`) are stored as rows dated `YYYY-12-31`.

`metric_key` follows the diff-key conventions already used by the scrapers, so do not split keys on separators, match them:
- CC: `assignments.Residential POMS.assignmentsReceived`, `reinspections.numberCompleted`, `summary.totalRevenue`
- Sedgwick: `overallCustomerSatisfaction`, `score_<workType>_myScore`, `score_<workType>_stateAvg`
- Alacrity: `totalCIPScore`, `emergency_cipScore`, `emergency_slas_contactInsured_actual` / `_target` (from `flattenCIPData`)

## Important Patterns

- Dates are stored as `YYYY-MM-DD` strings in Central Time (`America/Chicago`)
- After editing `index.html.bak`, run `npm run encrypt` to regenerate the encrypted `index.html`
- The encryption scripts share crypto logic (PBKDF2 rounds, AES-CBC) that must stay in sync across `encrypt.js`, `encrypt-data.js`, `decrypt.js`, and the injected client-side code
- `HEADLESS=false` env var runs scrapers with visible browser for debugging
